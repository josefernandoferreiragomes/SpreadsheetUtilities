Prompt Guide: dotnet-minimal-api
--------------------------------

Purpose
-------
Give concise example prompts and conventions for using the `dotnet-minimal-api` agent and the `git-operator` subagent.

Commit & Changelog Conventions
-----------------------------
- Commit title: short summary (<=72 chars)
- Commit body: include a `Changelog:` line with the changelog entry following the template:

  Changelog: <Type>: <Scope> — <one-line summary> — <author>

- Branch pattern: `<type>/<scope>/<short-summary>` (e.g., `feature/Auth.Api/add-health-check`).
- Changelog types: `Feature`, `Fix`, `Chore`.

How to ask the agent to persist changes
--------------------------------------
1. Ask the main agent to make changes and update `CHANGELOG.md` under `[Unreleased]`.
2. When ready, request the git plan: "Prepare branch `feature/...`, commit changed files, and show push plan." The agent will call `git-operator` and show the git commands.
3. Review the plan and explicitly confirm with: `confirm: git push` to allow pushing and opening PRs (if allowed). By policy here, PRs are manual; the subagent will not open PRs automatically.

Example Prompts
---------------
- "Add a health-check endpoint to `Auth.Api`, update `CHANGELOG.md`, and prepare a branch." 
- "Refactor `Program.cs` in `UI.Web` to use `MapGroup`, add tests, and show the git plan." 
- "Migrate `SpreadsheetUtilities.Auth.Api` to .NET 8 minimal-host; include migration notes in `docs/` and prepare a branch." 
- "Stage my changes, commit with the `[Unreleased]` changelog entry as the commit body, and show the push plan (do not push)."

Safety Notes
------------
- The subagent uses the local git user for commits and will not GPG-sign commits.
- The subagent will only prepare branches for manual PR creation; it will not create PRs automatically.
